# 룰 채택 기준

패턴 필터에 들어가는 룰은 이 문서의 기준을 모두 통과해야 한다. 패턴 필터는 차단 전용이며, 확실한 것만 차단한다. 룰이 잡지 못하는 문장은 판정 모델이 처리한다. ([constitution.md](constitution.md) 3장, [DECISIONS.md](../DECISIONS.md) 2026-10-26 룰 최소화 항목 참고)

상태: 승인 (2026-10-26 사용자 승인). 현재 채택된 패턴은 0개이며, 이 기준은 앞으로 패턴을 추가할 때 적용한다.

## 1. 목적

- 룰은 오탐 없이 확실하게 차단할 수 있는 표현에만 쓴다.
- 탐지율은 룰의 채택 기준이 아니다. 놓치는 공격은 판정 모델이 보완한다.

## 2. 채택 기준

룰 하나가 아래 네 가지를 모두 만족해야 채택한다.

| 번호 | 기준 | 확인 방법 |
|---|---|---|
| C1 | 룰의 자체 예시(매치 예시)가 모두 해당 룰에 일치한다. | 정규식을 Java로 실행해 예시마다 일치 여부를 확인한다. |
| C2 | 룰 심사용 정상 문장 풀의 두 층 모두에서 오탐이 0건이다. | 도메인 정상 풀과 일반 정상 풀의 모든 문장에 실행한다. 풀의 규모와 구성은 이 문서의 4장에 기록한다. |
| C3 | 룰마다 근거 문장이 있다. | `split=design` 공격 문장 중 이 룰이 대응하는 문장을 1개 이상 기록한다. |
| C4 | 사용자가 직접 선정하고, 확실한 이유를 적었다. | 룰 기록의 `이유` 항목을 사용자가 작성하거나 승인한다. |

## 3. 제외 기준

아래 중 하나라도 해당하면 채택하지 않는다.

1. 단독 키워드 룰. 예: "비밀번호", "연봉", "승인"만으로 차단하는 룰
2. 말투(명령형, 의문형)나 종결어미에 의존하는 룰
3. 타인과 본인을 구분해야만 성립하는 룰(F1~F3의 대부분). 이 구분은 판정 모델이 맡는다.
4. 정상 질문에서도 같은 문형으로 쓰이는 표현. 예: "결재 없이 진행 가능한가요?"처럼 규정을 묻는 질문과 구별되지 않는 룰
5. 자체 예시가 일치하지 않는 룰

## 4. 정상 문장 풀

- 구성: 두 층으로 나눈다. (1) 도메인 정상 풀: 한국어 HR/IT 정상 문장과 경계 문장. (2) 일반 정상 풀: `dataset.csv`의 `split=design` 정상 문장.
- 현재 규모: 도메인 50문장(정상 12, 경계 12, 보강 정상 8, 보강 경계 4, 스트레스 14), 일반 79문장(일반 32, hard negative 47). 합계 129문장.
- 목표 규모: 도메인 80문장. 남은 30문장(경계 15, 일반 15)은 룰이 정해진 뒤에 그 룰의 어휘 주변에서 표적으로 작성한다. 사용자 직접 작성은 약 40% 이상을 권장한다.
- 문체 균형: 정상 풀에 명령형 문장을, 공격 풀에 의문형 문장을 포함한다.
- 모든 문장에 출처(직접 작성 또는 AI 초안)와 사용자의 검수 여부를 기록한다.
- 이 풀은 `split=design`에 속한다. eval 문장은 룰 심사에 쓰지 않는다. ([constitution.md](constitution.md) 2장 참고)

## 5. 룰 기록 형식

룰마다 아래 항목을 기록한다.

| 항목 | 내용 |
|---|---|
| 룰 ID | 예: I3-01 |
| 대상 | I1~I4 또는 F4 등 |
| 패턴 | Java 정규식 |
| 근거 문장 | 대응하는 design 공격 문장 번호와 원문 |
| 이유 | 왜 확실한가 (사용자 작성) |
| 자체 예시 | 매치 예시 2개 이상 |
| 반례 | 일치하면 안 되는 정상 문장 2개 이상 |
| 출처 | 직접 작성, 외부 LLM 제안 후 수정 등 |
| 검증일과 결과 | C1, C2 통과 여부 |

## 6. 변경 규칙

- 룰을 추가하거나 고치면 C1~C4를 다시 확인한다.
- 정상 문장 풀이 늘어나면 기존 룰 전체를 다시 확인한다.
- 룰이 통과했다고 안전하다는 뜻은 아니다. 이 기준은 오탐을 줄이기 위한 최소 조건이다.
