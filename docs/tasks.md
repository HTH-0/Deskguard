## T13 실제 Jev 스모크 시험 (합격 기준은 실행 전인 2026-10-28에 고정)

- 목적: 측정 모드 서버, `run_batch.py`, 실제 Jev가 끝까지 이어지는지 확인한다. 탐지 정확도 평가가 아니다(정확도는 6단계).
- 입력: [poc/smoke_t13.csv](poc/smoke_t13.csv). `dataset.csv`의 design 분할 한국어 8문장이다(공격 3: 주입, 탈옥, 프롬프트 탈취 / 정상 3: 범위 밖 일반 질문 / 경계 정상 2: 보안 단어 포함, "무시하고" 포함). 제한 유형, 영어, eval은 없다. 비용은 호출 9건(확인 문장 1 + 8)으로 1센트 미만이다.
- 실행 위치: 사용자 컴퓨터(키가 있는 곳). 서버를 측정 모드로 띄우고 `backend/scripts`에서 `python run_batch.py --input ..\..\docs\poc\smoke_t13.csv --output smoke_result.csv --delay 0.5`를 실행한다.

| 번호 | 합격 기준 |
|---|---|
| a | 8건 모두 단계가 `NONE` 또는 `JUDGE`이다(`JUDGE_FAILURE`와 오류가 0건) |
| b | 모든 행에 점수 10개와 모델 `jev-1.14.0`이 있다 |
| c | 서버 로그의 `decision=` 줄이 9개(확인 문장 1 + 8)이고, 로그에 두 API 키 값이 없다 |
| d | 시작 시 모드 확인에서 중단되지 않고, 시작 문구에 "제외 ... 0건"이 나온다 |
| e | 서버가 받은 문장이 입력 8개와 확인 문장뿐이다(`decision=` 줄 수와 같다) |

- 합격 기준이 아닌 것: 어떤 문장이 차단되었는지(정확도). 마지막 경계 문장("무시하고")은 알려진 약점이라 차단될 수 있으며, 불합격이 아니라 관찰로만 기록한다.
- 불합격이면 `failureKind`로 원인을 나눈다. `CONFIG_ERROR`는 키, `RATE_LIMITED`는 한도(R9), `TIMEOUT`은 연결 문제이다. 이후 계획을 변경한다.
