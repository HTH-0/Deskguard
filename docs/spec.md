# 명세서 v2

직원이 외부 AI에 보내는 프롬프트를 나가기 전에 검사하는 게이트웨이가 무엇을 해야 하는지 정한다. 왜 만드는지는 [문제 정의서](problem.md), 무엇을 지키고 어떻게 처리하는지는 [위협 모델과 데이터 정책](policy.md)이 정하고, 이 문서는 그것을 수용 기준(AC)으로 옮긴다. 어떻게 만들지는 설계서(`design.md`, 2일차 작성)에서 다룬다.

상태: 확정 (2026-10-29 사용자 승인, 4장 결정 권장대로). 주제 재정의 이전의 명세(HR 헬프데스크 챗봇)는 [archive/spec-v1-hr.md](archive/spec-v1-hr.md)에 보관했다. 일정 때문에 AC 표 중심으로 짧게 쓴다.

## 1. 처리 흐름

```
POST /api/chat {prompt, confirmed?}
  1. 입력 검증        실패 → 400
  2. 탐지            D1 개인정보, D2 자격증명, D3 회사 기밀 (게이트웨이 안의 코드만)
  3. 처리 결정        차단 > 경고 > 가림 > 허용
  4. 차단            → 외부 AI 호출 없음, 범주와 개수만 알림
     경고(미확인)     → 외부 AI 호출 없음, 범주와 개수를 알리고 확인을 요청
     가림 또는 경고 확인 → 값을 가명으로 바꿔 외부 AI 호출
     허용            → 원문으로 외부 AI 호출
  5. 복원            응답의 가명을 원래 값으로 되돌림
  6. 감사 로그        한 줄, 원문과 탐지한 값 없음
```

## 2. 기능 요구사항과 수용 기준

### FR-1 입력 검증 (기존 재사용)

| 번호 | 수용 기준 |
|---|---|
| AC-1.1 | Given 비어 있거나 공백뿐인 prompt, When 요청한다, Then 400이고 외부 AI를 호출하지 않는다. |
| AC-1.2 | Given 최대 길이를 넘는 prompt, When 요청한다, Then 400이다. 최대 길이는 4,000자로 늘린다(명단과 설정 파일을 붙여넣는 업무 문장이 길기 때문이다). |

### FR-2 탐지

| 번호 | 수용 기준 |
|---|---|
| AC-2.1 | Given 검증 규칙을 통과하는 주민등록번호, 외국인등록번호, 휴대전화, 이메일, 계좌번호, 카드번호가 든 문장, When 탐지한다, Then 각 값을 D1의 해당 항목으로 찾는다(위치와 개수 포함). |
| AC-2.2 | Given 형식은 맞지만 검증 규칙에 실패하는 값(`000000-0000000`, Luhn 실패 카드번호 등), When 탐지한다, Then 찾지 않는다. |
| AC-2.3 | Given 알려진 키 형식, 개인 키 블록, 비밀번호 할당, 비밀번호가 든 접속 문자열, JWT가 든 문장, When 탐지한다, Then D2로 찾는다. |
| AC-2.4 | Given 회사 사전의 코드명, 고객사 이름, 보안 등급 표시가 든 문장, When 탐지한다, Then D3로 찾는다. |
| AC-2.5 | Given 허용 목록의 값(회사 대표 전화, 대표 이메일), When 탐지한다, Then 찾지 않는다. |
| AC-2.6 | Given 값 없이 형식만 묻는 문장("주민등록번호는 몇 자리야?"), When 탐지한다, Then 아무것도 찾지 않는다. |
| AC-2.7 | Given 탐지 규칙과 회사 사전, When 서버가 시작한다, Then 설정 파일에서 읽고, 잘못된 설정이면 시작하지 않는다. |
| AC-2.8 | Given 어떤 문장이든, When 탐지한다, Then 외부 서비스를 호출하지 않는다. |

### FR-3 처리 결정

| 번호 | 수용 기준 |
|---|---|
| AC-3.1 | Given 탐지 결과, When 처리를 정한다, Then policy.md 3장의 범주별 처리를 따르고, 여러 처리가 겹치면 차단 > 경고 > 가림 > 허용 순으로 가장 강한 것을 고른다. |
| AC-3.2 | Given D1 값이 대량 기준(policy.md P2) 이상인 문장, When 처리를 정한다, Then 경고이다. |
| AC-3.3 | Given 아무것도 탐지되지 않은 문장, When 처리를 정한다, Then 허용이다. |

### FR-4 가림과 복원

| 번호 | 수용 기준 |
|---|---|
| AC-4.1 | Given 가림 처리, When 외부 AI로 보낸다, Then 탐지한 값은 모두 `[전화1]`처럼 범주와 순번이 드러나는 가명으로 바뀌고, 원래 값은 하나도 남지 않는다. |
| AC-4.2 | Given 같은 값이 여러 번 나온 문장, When 가린다, Then 같은 가명으로 바뀐다. 다른 값은 다른 가명이다. |
| AC-4.3 | Given 가명이 든 응답, When 복원한다, Then 가명을 원래 값으로 되돌린다. 응답에 없는 가명은 무시하고, 대응표에 없는 가명 모양의 글자는 그대로 둔다. |
| AC-4.4 | Given 요청 하나, When 처리가 끝난다, Then 가명 대응표는 메모리에서 버려지고 파일, DB, 로그에 남지 않는다. 요청끼리 대응표를 공유하지 않는다. |
| AC-4.5 | Given 원문에 이미 `[전화1]` 같은 글자가 있다, When 가린다, Then 그 글자와 겹치지 않는 가명을 쓴다. |

### FR-5 외부 AI 호출 (기존 재사용)

| 번호 | 수용 기준 |
|---|---|
| AC-5.1 | Given 차단이나 확인 전 경고, When 처리한다, Then 외부 AI를 호출하지 않는다. |
| AC-5.2 | Given 외부 AI의 오류, When 처리한다, Then 기존 오류 형식으로 알리고 내부 정보(주소, 키, 외부 응답 본문)는 싣지 않는다. |

### FR-6 직원에게 돌려주는 응답

| 번호 | 수용 기준 |
|---|---|
| AC-6.1 | Given 허용이나 가림, When 응답한다, Then 복원된 답과 처리 결과(가림이면 범주별 개수)를 돌려준다. |
| AC-6.2 | Given 경고, When `confirmed` 없이 요청한다, Then 범주별 개수와 확인 요청을 돌려준다. When 같은 prompt를 `confirmed=true`로 다시 요청한다, Then 가림 처리로 보낸다(원문으로 보내지 않는다, policy.md P3). |
| AC-6.3 | Given 차단, When 응답한다, Then 범주별 개수와 이유만 돌려주고, 탐지한 값과 탐지 규칙은 싣지 않는다. |
| AC-6.4 | Given 가림, When 응답한다, Then 외부 AI로 실제로 보낸 가린 문장(`sentPrompt`)을 함께 돌려준다. 직원이 무엇이 나갔는지 확인하게 하기 위해서이다. 직원 자신이 쓴 문장에서 값만 바뀐 것이므로 새 정보를 드러내지 않는다. 위치는 싣지 않는다. (4일차 추가) |

### FR-7 감사 로그 (기존 재사용, 항목 변경)

| 번호 | 수용 기준 |
|---|---|
| AC-7.1 | Given 요청이 끝났다, When 로그를 본다, Then 요청 ID, 범주별 개수, 처리 결과, 원문의 길이와 해시, 단계별 지연이 한 줄로 있다. |
| AC-7.2 | Given 어떤 요청이든, When 로그를 본다, Then 원문, 탐지한 값, 가명 대응표, API 키가 없다. |

### FR-8 사내 AI 포털 (화면)

| 번호 | 수용 기준 |
|---|---|
| AC-8.1 | Given 포털, When 직원이 문장을 보낸다, Then 답과 함께 가림 처리 여부와 범주별 개수가 보인다. |
| AC-8.2 | Given 경고, When 포털이 확인을 요청한다, Then 직원은 "가려서 보내기" 또는 "취소"를 고른다. |
| AC-8.3 | Given 차단, When 포털이 알린다, Then 직원은 무엇을 지우고 다시 보내야 하는지 범주로 안다. |

화면 완성도는 평가 대상이 아니다(constitution 1장 5번). 정적 HTML 한 장으로 만든다.

### FR-9 측정 모드 (기존 재사용, 응답 항목 변경)

| 번호 | 수용 기준 |
|---|---|
| AC-9.1 | Given 측정 모드가 꺼져 있다, When 요청한다, Then 응답에 내부 탐지 정보(위치, 항목)가 없다. |
| AC-9.2 | Given 측정 모드가 켜져 있고 같은 컴퓨터의 요청이다, When 요청한다, Then 외부 AI를 호출하지 않고 처리 결과, 범주별 항목과 개수, 가린 문장, 단계별 지연을 돌려준다. |
| AC-9.3 | Given 측정 모드가 켜져 있어도 다른 컴퓨터의 요청이다, When 요청한다, Then 측정 응답을 주지 않는다(헤더를 믿지 않는다). |
| AC-9.4 | Given 측정 모드가 켜져 있고 가림 처리된 요청이다, When 요청한다, Then 가린 문장을 그대로 복원 단계에 통과시켜 복원 지연(`restoreMs`)을 채우고, 복원한 문장은 원문과 같다. 외부 AI는 여전히 부르지 않는다. |

### FR-10 평가 (X, Y, Z, T)

| 번호 | 수용 기준 |
|---|---|
| AC-10.1 | Given 평가 세트, When 만든다, Then 업무 요청 틀(생성기)과 가짜 민감 값(코드)을 합쳐 만들고, 넣은 값의 범주와 위치가 정답으로 함께 저장된다. 민감 값이 없는 정상 업무 문장도 포함한다. 실제 개인정보는 쓰지 않는다. |
| AC-10.2 | Given 평가 세트, 탐지 설정, 대량 기준, When 측정한다, Then 측정 전에 파일 해시로 동결하고, 동결 뒤에는 바꾸지 않는다. |
| AC-10.3 | Given 측정 결과, When 보고한다, Then X(범주별 탐지율), Y(정상 문장의 오탐율), T(검사, 가림, 복원의 지연)를 윌슨 95% 구간과 함께 적는다. |
| AC-10.4 | Given 가림 처리된 평가 문장, When Z를 잰다, Then 원문으로 받은 답 A와 가림 후 복원한 답 B를 받고, 복원 성공률은 코드로, 쓸모 판정은 Jev로 채점한다. 이 측정 경로는 가짜 데이터로만 하고 운영 경로와 코드와 설정을 분리한다. |
| AC-10.5 | Given Jev 채점, When 채택 여부를 정한다, Then 사람이 판정한 40~50쌍과의 일치율이 85% 이상일 때만 채택하고, 미달이면 사람 판정과 한계 기록으로 바꾼다. |
| AC-10.1a | Given 평가 세트 파일, When 저장한다, Then 한 줄이 JSON 한 건이며 `id`, `text`, `kind`(`sensitive` 또는 `normal`), `expected_action`, `spans[{category,item,start,end}]`를 가진다. 정상 문장은 `spans`가 비어 있다. |
| AC-10.1b | Given 평가 세트 규모, When 만든다, Then 값 항목마다 30개 이상, 정상 문장 100개 이상, 대량 기준 시나리오 10개 이상을 둔다. |
| AC-10.3a | Given 탐지 일치 판정, When X를 센다, Then 정답과 항목이 같고 구간이 1글자 이상 겹치면 탐지(TP)로 센다. 범주만 같고 항목이 다르면 "범주 일치, 항목 오류"로 따로 센다. 정답에 없는 탐지는 FP, 놓친 정답은 FN이다. |
| AC-10.3b | Given X의 단위, When 보고한다, Then 범주별(D1, D2, D3) 값 단위 탐지율을 주지표로, 문장 단위 처리 정확도(기대 처리와 실제 처리 일치율)를 보조지표로 적는다. |
| AC-10.3c | Given 정상 문장, When Y를 센다, Then 처리가 ALLOW가 아니거나 탐지가 1개 이상이면 오탐 한 건으로 센다. |
| AC-10.3d | Given T, When 보고한다, Then 측정 응답의 검사, 가림, 복원 지연을 중앙값과 95백분위로 적고, 도구가 잰 HTTP 왕복 시간을 함께 적는다. 서버 지연은 밀리초 단위로 재므로 1ms 미만은 구분하지 못한다는 한계를 적는다. |
| AC-10.6 | Given 측정을 마쳤다, When 보고서를 쓴다, Then 놓친 사례, 우회 시험(띄어쓰기, 한글 숫자 등 소수) 결과, 한계(합성 문장, 사전 기반 D3, D4 제외)가 함께 있다. |

## 3. 비기능 요구사항

| 번호 | 요구사항 |
|---|---|
| NFR-1 | API 키는 환경변수로만 주입하고 소스, 설정, 테스트, 로그에 적지 않는다(기존). |
| NFR-2 | 자동 테스트는 외부 AI와 Jev를 호출하지 않고 키 없이 통과한다(기존). |
| NFR-3 | 검사, 가림, 복원은 요청당 수십 ms 안에 끝나는 것을 목표로 한다. 실제 값은 T로 측정한다. |
| NFR-4 | 운영 경로는 외부 판정 서비스를 호출하지 않는다(problem.md 4장). |
