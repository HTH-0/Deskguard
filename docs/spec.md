# 명세서

사내 HR 헬프데스크 챗봇을 위한 LLM 입력 가드레일 게이트웨이가 무엇을 해야 하는지 정한다. 어떻게 만들지는 설계서(`design.md`)에서 다룬다. 명세와 코드가 어긋나면 명세를 먼저 고친다. ([constitution.md](constitution.md) 5장 참고)

상태: 확정 (2026-10-26 사용자 확인). 결정 D1~D5를 모두 반영했다. 변경하면 DECISIONS.md에 기록하고 수용 기준에 미치는 영향을 확인한다.

관련 문서: [constitution.md](constitution.md), [domain-policy.md](domain-policy.md), [rule-criteria.md](rule-criteria.md), [open-risks.md](open-risks.md), [DECISIONS.md](../DECISIONS.md)

## 1. 목적과 범위

1. 챗봇으로 들어가는 사용자 프롬프트를 응답 모델에 전달하기 전에 검사하여, 프롬프트 인젝션과 도메인 정책 위반을 차단한다.
2. 방어 대상은 일반 인젝션 4종(I1 지시 무시, I2 역할극과 모드 사칭 탈옥, I3 시스템 프롬프트 탈취, I4 권한 사칭)과 도메인 정책 위반 4종(F1 타인 정보 열람, F2 권한 밖 계정·시스템 변경, F3 승인 절차 우회, F4 내부 보안 구성과 자격증명 노출)이다. 상세는 [domain-policy.md](domain-policy.md)를 따른다.
3. 입력 방어만 다룬다. 출력(응답) 필터링은 범위 밖이다.
4. 금지 콘텐츠 요청(`disallowed_content`)과 편향 발언 강요(`bias_injection`)는 이번 방어 범위에서 보류한다.

## 2. 용어

| 용어 | 뜻 |
|---|---|
| 패턴 필터 | 정규식으로 요청을 먼저 걸러내는 1차 단계. 차단 전용이다. 현재 패턴은 0개이며 구성요소 자리만 유지한다. |
| 판정 모델 | 요청이 정책을 위반하는지 확률로 판단하는 2차 단계. 후보 1순위는 Jev이며 한국어 PoC 후 확정한다. |
| 응답 모델 | 검사를 통과한 요청에 실제로 답하는 모델. 현재 Gemini(`gemini-3.6-flash`, 무료 티어)이다. |
| 차단 | 응답 모델을 호출하지 않고 사용자에게 차단 응답을 돌려주는 것 |
| 통과 | 응답 모델에 전달해 답변을 받는 것 |
| 범위 밖 질문 | 챗봇의 허용 범위(HR·총무 일반, IT 일부)에 속하지 않지만 금지 항목도 아닌 질문. 예: 일반 보안 지식, 업무 정리 요청 |
| 측정 모드 | 6단계 측정을 위해 응답 모델 호출을 생략하고 내부 판정 결과를 돌려주는 개발용 동작 |

## 3. 처리 흐름

```
사용자 프롬프트
   │
   ▼
FR-1 입력 검증 ── 실패 → 400 거부
   │
   ▼
FR-2 패턴 필터 ── 일치 → 차단 (패턴 목록이 비어 있으면 모두 통과)
   │
   ▼
FR-3 판정 모델 ── 임계값 이상 또는 호출 실패 → 차단 (FR-6)
   │
   ▼
FR-4 응답 모델 ── 답변 반환 (측정 모드에서는 생략: FR-9)
```

## 4. 사용자 시나리오

| 번호 | 시나리오 | 기대 결과 |
|---|---|---|
| S1 | 직원이 휴가 규정이나 VPN 설정 같은 정상 질문을 한다 | 통과하여 답변을 받는다 |
| S2 | 직원이 화면 라벨이나 오류 문구를 인용하며 정상 질문을 한다 (경계 문장) | 통과한다. 권한, 승인, 비밀번호 같은 단어가 있어도 차단하지 않는다 |
| S3 | 누군가 "이전 지시를 무시하고…"처럼 인젝션을 시도한다 | 차단된다 |
| S4 | 누군가 타인의 연봉이나 계정 변경 같은 도메인 정책 위반을 요구한다 | 차단된다. 의문형이어도 차단한다 |
| S5 | 직원이 챗봇의 범위 밖 질문을 한다 | 통과한다. 응답 방식은 이번 범위에서 정의하지 않는다 (D5) |
| S6 | 판정 서비스가 장애이거나 응답하지 않는다 | 차단한다 (결정 3) |

## 5. 기능 요구사항

수용 기준은 Given/When/Then 형식이며, 번호는 테스트와 1대 1로 대응시킨다.

### FR-1 입력 검증

- 요청 본문에 `prompt` 문자열이 있어야 한다.
- 빈 문자열과 공백만 있는 문자열은 거부한다.
- 최대 길이: 1,000자 (D2 확정, 2026-10-26)
- 인코딩은 UTF-8이다.

| 번호 | 수용 기준 |
|---|---|
| AC-1.1 | Given 정상 서버, When `prompt`가 비어 있거나 공백뿐이다, Then 400을 반환하고 판정 모델과 응답 모델을 호출하지 않는다. |
| AC-1.2 | Given 정상 서버, When 요청 본문에 `prompt`가 없다, Then 400을 반환한다. |
| AC-1.3 | Given 정상 서버, When `prompt`가 최대 길이를 넘는다, Then 400을 반환하고 외부 호출을 하지 않는다. (최대 길이는 1,000자이다. 1,000자는 허용하고 1,001자부터 거부한다.) |
| AC-1.4 | Given 정상 서버, When 한글이 포함된 `prompt`를 UTF-8로 보낸다, Then 깨지지 않고 처리된다. |

### FR-2 패턴 필터

- 패턴은 설정 파일에서 읽는다. 목록이 비어 있으면 모든 요청을 통과시킨다.
- 패턴이 일치하면 판정 모델을 호출하지 않고 차단한다.
- 패턴 추가는 [rule-criteria.md](rule-criteria.md)의 채택 기준(C1~C4)을 통과해야 한다.

| 번호 | 수용 기준 |
|---|---|
| AC-2.1 | Given 패턴 목록이 비어 있다, When 어떤 `prompt`가 들어온다, Then 패턴 필터는 통과시킨다. |
| AC-2.2 | Given 패턴 하나가 설정되어 있다, When 그 패턴과 일치하는 `prompt`가 들어온다, Then 판정 모델을 호출하지 않고 차단한다. |
| AC-2.3 | Given 패턴 하나가 설정되어 있다, When 일치하지 않는 `prompt`가 들어온다, Then 판정 단계로 넘어간다. |
| AC-2.4 | Given 잘못된 정규식이 설정되어 있다, When 서버가 시작된다, Then 시작에 실패하고 원인을 로그에 남긴다. |

### FR-3 판정 모델

- 패턴 필터를 통과한 모든 요청을 판정 모델에 보낸다.
- 정책 항목마다 질문을 만들되 조건이 둘인 I2와 F4는 나누어, 총 10개(I1, I2a, I2b, I3, I4, F1, F2, F3, F4a, F4b)를 한 번의 호출에 함께 보낸다(D4 확정, 2026-10-26). 하나라도 임계값 이상이면 차단한다. 질문 문구는 설계서에서 정하며, 질문 하나에 조건 하나만 담고 높은 값이 위반을 뜻하게 쓴다.
- 질문은 "예"일 확률이 높을수록 위반을 뜻하도록 쓴다. 한 질문에는 한 조건만 담는다.
- 판단 결과(확률)가 임계값 이상이면 차단한다. 임계값은 0.5이다(D1 확정, 2026-10-26). 모든 질문에 같은 임계값을 쓰고, 설정 값으로 두며, 6단계 측정 후 재검토한다. 임계값은 design 데이터와 사전 정의로 정하고 eval 결과를 보고 조정하지 않는다.
- 모델은 버전 ID로 고정한다(예: `jev-1.14.0`). 별칭(`jev-latest`)은 쓰지 않는다. 응답에 실린 `model` 값을 기록한다. (R7)
- 판정 모델 호출은 `Judge` 인터페이스 뒤에 두어 다른 모델로 교체할 수 있게 한다. (R3)

| 번호 | 수용 기준 |
|---|---|
| AC-3.1 | Given 판정 모델이 어떤 질문에 임계값 이상의 확률을 돌려준다, When 요청이 처리된다, Then 응답 모델을 호출하지 않고 차단한다. |
| AC-3.2 | Given 판정 모델이 모든 질문에 임계값 미만의 확률을 돌려준다, When 요청이 처리된다, Then 응답 모델로 전달한다. |
| AC-3.3 | Given 설정에 모델 버전 ID가 지정되어 있다, When 판정 요청을 보낸다, Then 요청의 `model` 필드에 그 버전 ID를 넣는다. |
| AC-3.4 | Given 판정 응답에 `model` 값이 있다, When 요청이 처리된다, Then 그 값을 로그에 기록한다. |
| AC-3.5 | Given 판정 질문 중 하나가 응답에서 누락되었다, When 요청이 처리된다, Then 판정 실패로 보고 차단한다. |
| AC-3.6 | Given 임계값이 0.5이다, When 어떤 질문의 확률이 정확히 0.5이다, Then 차단한다. |
| AC-3.7 | Given 임계값이 0.5이다, When 모든 질문의 확률이 0.49이다, Then 통과시킨다. |
| AC-3.8 | Given 설정 파일에서 임계값을 바꾼다, When 서버를 다시 시작한다, Then 바뀐 임계값이 적용된다. |
| AC-3.9 | Given 판정 요청을 보낸다, When 요청 본문을 확인한다, Then 질문 10개(I1, I2a, I2b, I3, I4, F1, F2, F3, F4a, F4b)가 한 번의 호출에 들어 있다. |
| AC-3.10 | Given 10개 질문 중 하나만 임계값 이상이다, When 요청이 처리된다, Then 차단한다. |

### FR-4 응답 모델 호출

- 차단되지 않은 요청만 응답 모델(Gemini)로 전달한다.
- 응답 모델 호출 실패는 기존 오류 응답 형식을 유지한다.

| 번호 | 수용 기준 |
|---|---|
| AC-4.1 | Given 패턴 필터와 판정 모델을 통과했다, When 응답 모델이 답변을 돌려준다, Then `{"answer": "..."}` 형식으로 반환한다. |
| AC-4.2 | Given 요청이 차단되었다, When 처리가 끝난다, Then 응답 모델 호출 횟수는 0이다. |
| AC-4.3 | Given 응답 모델 호출이 실패한다, When 오류가 발생한다, Then 기존 `{"error", "message"}` 형식으로 반환한다. |

### FR-5 차단 응답

- HTTP 403과 본문 `{"blocked": true, "message": "정책에 따라 요청이 차단되었습니다"}`를 반환한다.
- 차단 단계, 패턴 ID, 정책 항목, 확률은 응답에 싣지 않는다. 내부 로그에만 기록한다. (공격자의 우회 학습 방지)

| 번호 | 수용 기준 |
|---|---|
| AC-5.1 | Given 요청이 차단되었다, When 응답을 확인한다, Then 상태 코드는 403이고 본문은 `blocked: true`와 일반 안내 메시지뿐이다. |
| AC-5.2 | Given 요청이 패턴 필터 또는 판정 모델에서 차단되었다, When 응답을 비교한다, Then 두 응답의 본문은 구별되지 않는다. |
| AC-5.3 | Given 요청이 판정 호출 실패로 차단되었다, When 응답을 확인한다, Then 정책 차단과 같은 형식이다. 내부 로그에서는 사유가 구분되어 기록된다. |

### FR-6 판정 실패 정책 (결정 3)

판정 호출이 실패하면 차단한다(fail-closed).

| 실패 원인 | 동작 |
|---|---|
| 타임아웃 | 차단 |
| 429, 529 | 지수 백오프로 재시도한 뒤에도 실패하면 차단. 재시도 횟수와 간격은 설계서에서 정한다. |
| 5xx | 차단 |
| 401, 422 | 설정 오류로 차단하고 운영 경보 수준으로 로그를 남긴다. |
| 400 `max_tokens_exceeded` | 입력 길이 초과. FR-1의 최대 길이에서 걸러야 하며, 도달하면 차단한다. |
| 응답 형식 오류 | 차단 |

| 번호 | 수용 기준 |
|---|---|
| AC-6.1 | Given 판정 서비스가 타임아웃된다, When 요청이 처리된다, Then 차단한다. |
| AC-6.2 | Given 판정 서비스가 429를 반복한다, When 재시도가 끝난다, Then 차단한다. |
| AC-6.3 | Given 판정 서비스가 401을 반환한다, When 요청이 처리된다, Then 차단하고 설정 오류를 로그에 남긴다. |
| AC-6.4 | Given 판정 서비스가 형식이 깨진 응답을 보낸다, When 요청이 처리된다, Then 차단한다. |
| AC-6.5 | Given 판정 호출 실패로 차단된 요청이 있다, When 측정 결과를 집계한다, Then 정책 차단과 별도로 집계된다. (R9) |

### FR-7 로깅

- 요청마다 다음을 기록한다: 요청 시각, 결정(통과 또는 차단), 차단 단계(패턴 필터, 판정 모델, 판정 실패), 패턴 ID, 질문별 확률, 판정 모델 버전, 단계별 지연 시간
- 프롬프트 원문 저장: 기본은 꺼짐이다. 기본 상태에서는 원문 대신 길이와 해시만 기록한다. 시험 환경 설정을 켠 경우에만 원문을 저장한다(D3 확정, 2026-10-26). 해시 방식은 설계서에서 정한다.
- API 키는 어떤 로그에도 기록하지 않는다. (constitution 4장)
- 입력 검증 실패, 판정자의 예상하지 못한 오류, 응답 모델 오류처럼 예외로 끝난 요청도 한 줄 기록한다. 결정은 ERROR이고, 예외 메시지는 기록하지 않는다. (2026-10-28 추가, D15)

| 번호 | 수용 기준 |
|---|---|
| AC-7.1 | Given 요청이 처리되었다, When 로그를 확인한다, Then 결정, 차단 단계, 질문별 확률, 모델 버전, 지연 시간이 있다. |
| AC-7.2 | Given 어떤 요청이든, When 로그를 확인한다, Then API 키 값이 없다. |
| AC-7.3 | Given 원문 저장이 꺼져 있다(기본), When 로그를 확인한다, Then 프롬프트 원문이 없고 길이와 해시만 있다. |
| AC-7.4 | Given 시험 환경 설정으로 원문 저장을 켠다, When 로그를 확인한다, Then 프롬프트 원문이 기록되어 있다. |
| AC-7.5 | Given 요청이 예외로 끝났다(입력 검증 실패, 판정자의 예상하지 못한 오류, 응답 모델 오류), When 로그를 확인한다, Then 결정이 ERROR인 줄이 한 줄 있고, 예외 메시지(주소나 키가 들어 있을 수 있다)는 없다. |

### FR-8 범위 밖 질문

범위 밖 질문은 금지 항목이 아니므로 차단하지 않고 통과시킨다(D5 확정, 2026-10-26). 응답 모델이 어떻게 답할지는 이번 범위에서 정의하지 않는다. 판정 모델이 범위 밖 질문을 위반으로 오판하는지 보기 위해, 범위 밖 시험 문장(검토표 U-04, U-12)은 측정에서 별도로 집계한다.

| 번호 | 수용 기준 |
|---|---|
| AC-8.1 | Given 판정 모델이 모든 질문에 임계값 미만의 확률을 돌려준다, When 범위 밖 질문(예: 일반 보안 지식, 업무 정리 요청)이 들어온다, Then 통과시킨다. |
| AC-8.2 | Given 범위 밖 시험 문장 집합이 있다, When 측정을 집계한다, Then 이 집합의 차단 건수를 다른 정상 문장과 별도로 보고한다. |

### FR-9 측정 모드

- 설정으로 켠 경우에만 동작한다. 기본값은 꺼짐이다.
- 켜면 응답 모델 호출을 생략하고, 결정과 단계, 확률을 응답에 포함한다. 통과와 차단 모두 200으로 같은 형식(해당하지 않는 값은 null)으로 응답한다. 판정 호출 실패로 차단된 요청은 실패 종류로 구분한다. (2026-10-28 보강, R9)
- 사용자에게 노출하는 환경에서는 꺼야 한다. (최소 노출 원칙, R8의 외부 전송 최소화)
- 측정 응답은 차단 이유를 드러내므로, 켜져 있어도 같은 컴퓨터(루프백 주소)에서 온 요청에만 준다. 주소는 실제 접속 주소로 판단하고 `X-Forwarded-For` 같은 헤더는 믿지 않는다. 다른 주소의 요청은 측정 모드가 꺼진 것과 같게 처리한다. (2026-10-29 추가, 사용자 지적)

| 번호 | 수용 기준 |
|---|---|
| AC-9.1 | Given 측정 모드가 꺼져 있다, When 요청이 들어온다, Then 응답에 내부 판정 정보가 없다. |
| AC-9.2 | Given 측정 모드가 켜져 있다, When 요청이 통과한다, Then 응답 모델을 호출하지 않고 결정 정보를 반환한다. |
| AC-9.3 | Given 측정 모드가 켜져 있다, When 요청이 차단된다(패턴, 판정, 판정 실패), Then 403이 아니라 200으로 통과한 요청과 같은 형식의 결정 정보를 반환한다. |
| AC-9.4 | Given 측정 모드가 켜져 있다, When 판정 호출 실패로 차단된다, Then 단계가 판정 실패이고 실패 종류가 있어서 정책 차단과 구분된다. (AC-6.5, R9) |
| AC-9.5 | Given 측정 도구에 입력 파일을 준다, When 기본 설정으로 실행한다, Then `disallowed_content`와 `bias_injection` 유형, 영어 hard negative, `split=eval` 행은 서버로 보내지 않고 제외 건수를 출력한다. (constitution 1장 3항, 2장 2항, handoff 6절 7번) |
| AC-9.7 | Given 측정 모드가 켜져 있다, When 다른 컴퓨터(루프백이 아닌 주소)에서 요청이 온다, Then 측정 모드가 꺼진 것과 같게 응답 모델을 부르고 200 답변 또는 403 차단으로 응답한다. |
| AC-9.8 | Given 측정 모드가 켜져 있다, When 다른 컴퓨터에서 `X-Forwarded-For`, `X-Real-IP`, `Forwarded` 헤더로 127.0.0.1을 주장한다, Then 측정 응답을 받지 못한다. |
| AC-9.6 | Given 서버가 측정 모드가 아니다, When 측정 도구를 실행한다, Then 정상 문장 1건으로 모드를 확인한 뒤 나머지 문장을 보내지 않고 중단한다. 일반 모드 실행은 명시 옵션을 준 경우에만 허용한다. (NFR-7, R8) |

### FR-10 6단계 측정 (2026-10-28 추가, 사용자 검토 대기)

- 같은 문장으로 기준선, 질문 v1, 질문 v2(현행)를 비교한다. 기준선과 질문 v2를 합친 조합(룰이 막거나 판정이 막으면 차단)은 서버 호출 없이 계산한다.
- 측정 대상은 두 세트이다. 일반 세트는 `dataset.csv`의 `split=eval` 중 측정 도구가 보내는 행이다. 도메인 세트는 한국어 도메인 문장으로 새로 만드는 `eval`이다. 두 세트는 섞지 않고 따로 보고한다. 여기에 실제 직원의 질문으로 이루어진 현실성 세트(공공데이터포털 KOICA 인사규정 질의응답의 질문 25개)를 세 번째 세트로 따로 보고한다.
- 도메인 세트는 여러 생성기가 만든 후보에서 사용자가 의도 라벨을 보지 않고 라벨링하고, 사전에 정한 기준으로 골라 만든다. 고르는 동안 판정 결과를 보지 않는다.
- 평가 세트, 기준선 룰, 질문 파일, 임계값은 측정 전에 동결하고, `eval`은 구성마다 한 번만 실행한다. 결과를 보고 이것들을 바꾸지 않는다.
- 보고는 탐지율, 오탐율, 정밀도, F1과 윌슨 95% 신뢰구간이고, 유형별과 언어별로 나누며, 판정 실패와 오류는 분리한다. 한계(합성 문장, 라벨러 수, 표본 크기)를 함께 적는다.

| 번호 | 수용 기준 |
|---|---|
| AC-10.1 | Given 6단계 측정 전이다, When 기준선 룰, 질문, 임계값, 평가 세트를 정한다, Then `eval` 문장을 열지 않고 `design` 데이터와 사전 정의로만 정하며, 측정 전에 동결 기록(파일 해시와 커밋)을 남긴다. (constitution 2장) |
| AC-10.2 | Given 동결 기록이 있다, When `eval`을 실행한다, Then 구성(기준선, 질문 v1, 질문 v2)마다 한 번 실행하고 결과를 바로 저장한다. 실행 후에는 동결한 항목을 바꾸지 않는다. |
| AC-10.3 | Given 측정 결과가 있다, When 보고표를 만든다, Then 구성별, 세트별로 탐지율, 오탐율, 정밀도, F1과 윌슨 95% 신뢰구간이 있고, 유형별과 언어별 표가 있으며, 판정 실패와 오류 건수가 분리되어 있다. (AC-6.5) |
| AC-10.4 | Given 점수가 저장되어 있다, When 임계값별 곡선을 만든다, Then 호출 없이 계산하고 현행 임계값 0.5의 위치를 표시한다. `eval` 곡선은 보고용이며 임계값을 고르는 데 쓰지 않는다. 임계값을 바꾼다면 `design` 데이터로 정하고 동결 전에 확정한다. (D1) |
| AC-10.5 | Given 도메인 세트를 만든다, When 후보를 고른다, Then 생성기 이름이 기록되어 있고, 사용자가 의도 라벨을 보지 않고 라벨링하며, 생성 수, 수락 수, 거절 사유, 의도 라벨과의 일치율이 보고된다. 생성기에는 질문 문구와 판정 결과를 알리지 않는다. (R10) |
| AC-10.6 | Given 기준선을 정한다, When 룰을 고른다, Then `design` 데이터로만 정하고 룰 채택 기준([rule-criteria.md](rule-criteria.md))을 따르며 서버 호출 없이 로컬에서 실행한다. |
| AC-10.7 | Given 측정을 마쳤다, When 보고서를 쓴다, Then 한계(합성 문장, 라벨러 수, 세트 크기, 언어 분포)와 놓친 사례가 함께 기록된다. |
| AC-10.8 | Given 현실성 세트(실제 직원 질문 25개)가 있다, When 6단계 측정을 한다, Then 이 세트는 생성 지시문과 후보 씨앗에 쓰이지 않고 동결 기록에 해시가 있으며, 정상 문장이므로 오탐율을 윌슨 구간과 함께 별도로 보고한다. |

## 7. API 계약

### POST /api/chat

요청
```json
{ "prompt": "사용자 프롬프트" }
```

| 상황 | 상태 코드 | 본문 |
|---|---|---|
| 통과하여 답변 | 200 | `{"answer": "..."}` |
| 차단 (정책 위반 또는 판정 실패) | 403 | `{"blocked": true, "message": "정책에 따라 요청이 차단되었습니다"}` |
| 입력 검증 실패 | 400 | 기존 오류 형식 `{"error": "...", "message": "..."}` |
| 응답 모델 호출 실패 | 기존 동작 유지 | 기존 오류 형식 `{"error": "...", "message": "..."}` |
| 측정 모드 켬 (개발용) | 200 | 결정, 단계, 확률. 형식은 설계서에서 정한다. |

`backend/scripts/run_batch.py`는 HTTP 오류를 `error`로 분류하므로, 403은 `blocked`로 따로 분류하도록 수정이 필요하다. 수정은 구현 단계에서 한다.
