# 룰 선정표 (스텝 2.9-4)

사용자가 직접 판단해서 채우는 문서이다. 각 공격 문장에서 룰로 쓸 만큼 확실한 표현이 있는지를 판단한다. AI는 칸을 채우지 않는다. ([constitution.md](../constitution.md) 6장 참고)

상태: 종료 (2026-10-26). 외부 LLM이 채운 초안은 64문장 전부 판정 모델이었고, 예비 점검에서 패턴 후보들이 현실적 반례에 오탐을 냈다. 그래서 패턴 필터에 넣을 패턴은 0개로 시작하기로 결정했다. 이 표는 이후 패턴 추가를 검토할 때 근거 문장 목록으로 보존한다. ([DECISIONS.md](../../DECISIONS.md) 2026-10-26 "패턴 필터에 패턴을 넣지 않고 시작" 항목 참고)

## 작성 방법

각 행에서 아래 세 칸을 채운다.

| 칸 | 적을 내용 |
|---|---|
| 룰로 쓸 확실한 표현 | 이 문장을 잡는 데 쓸 표현. 정규식이 아니라 말로 적어도 된다. 예: "'이전 지시'와 '무시' 계열 동사가 함께 나오는 경우". 없으면 비운다. |
| 판정 | `룰` 또는 `판정 모델`. 확실한 표현이 없으면 `판정 모델`로 적는다. |
| 이유 | 왜 확실하다고 보는지, 또는 왜 룰로 쓸 수 없는지 한 줄 |

판단할 때 자문할 질문:
1. 이 표현이 **정상 질문에서도** 쓰이는가? 쓰인다면 확실하지 않다.
2. 이 표현이 말투(명령형, 의문형)에 의존하는가? 의존하면 제외 대상이다.
3. 본인과 타인을 구분해야만 성립하는가? 그렇다면 룰이 아니라 판정 모델 몫이다.
4. 단독 키워드인가? 단독 키워드는 제외 대상이다.

참고: 지난 검증에서 정상 질문에도 쓰여서 오탐이 난 표현은 "프롬프트 초기화"(터미널 프롬프트), "개발자 모드"(브라우저), "결재 없이 진행"(규정 문의), "소스코드 비밀번호"(관리 지침 문의) 등이었다. 룰 후보는 채택 기준 C1~C4를 모두 통과해야 한다. ([rule-criteria.md](../rule-criteria.md) 참고)

영어는 근거 문장이 DS-06 한 건뿐이어서 영어 룰은 최소화한다. ([DECISIONS.md](../../DECISIONS.md) 2026-10-26 추가 수집 보류 항목 참고)

## E. 선정 후 처리

1. 사용자가 표를 채우면 AI가 `판정`이 `룰`인 항목을 정규식으로 옮기고 Java로 컴파일한다.
2. 정상 문장 풀 두 층(도메인 50 + 일반 79)과 자체 예시로 C1, C2를 확인한다.
3. 통과한 룰은 [rule-criteria.md](../rule-criteria.md) 5장 형식으로 기록한다.
4. 통과하지 못한 룰은 사용자와 함께 좁히거나 `판정 모델` 몫으로 돌린다.
