# 코드 읽기 진행 기록

확인 질문에 답하고 틀린 곳을 바로잡은 파일만 "확인 완료"로 적는다. 읽기만 한 파일은 "확인 대기"이다.

## 2026-10-29 (1일차)

| 파일 | 상태 | 남은 일 |
|---|---|---|
| `ChatGateway` | 읽음, 핵심 흐름 이해. 확인 대기 | 가이드 질문 4(가명 대응표가 사라지는 곳), 5(오류 로그 내용)는 답하지 않았다 |
| `ActionDecider` | 읽음. 확인 대기 | 처음에 WARN과 MASK 조건을 반대로 읽었다가 바로잡았다. 확인 질문 3개(전화번호 5개와 고객사 3개, 이메일 20개와 대외비, 코드명 30개가 경고가 아닌 이유)에 답하면 확인 완료 |
| `InputValidator` | `validate` 동작은 파악. 확인 대기 | 가이드 질문 4: 주석의 "기본 1,000자"와 실제 설정값(`application.yml`) 비교 |
| `ChatController` | 읽지 않음 | `measure`가 어디서 만들어지는지(41~43줄)는 대화에서 연결해 봄 |
| `DetectionEngine` | 일부 읽음 | `detect`의 4단계는 설명을 들음. 2일차에 이어서 읽기 |
| `SecretDetector` | 일부 읽음 | `password=abc`가 탐지되지 않는 이유(28줄 `{4,}`)를 확인함. 2일차에 이어서 읽기 |

### 오늘 바로잡은 오해

1. `measure`는 마스크 여부를 정하는 스위치가 아니라 컨트롤러가 (서버 설정 + 같은 컴퓨터 여부)로 계산해 넘기는 "측정 요청 여부"이다.
2. 이름이 가려지지 않는 것은 허용 목록 때문이 아니라 탐지 대상이 아니기 때문이다.
3. 위험도 순서는 `ActionDecider`와 `DetectionEngine` 겹침 정리에서만 쓰이고, `handle()`의 흐름 순서는 "보내기 전에 검사"가 이유이다.
4. D1이 하나만 있으면 MASK이고, WARN은 D1이 대량 기준(20개) 이상일 때만이다.
