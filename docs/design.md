# 설계서

[spec.md](spec.md)의 요구사항을 어떻게 만족시킬지 정한다. 1~4절은 판정 질문과 약점 개선, 5~9절은 구조, 판정 호출, 로깅, 테스트 전략이다. 모두 2026-10-27에 사용자가 확정했다.

상태: 확정 (2026-10-27). 구현 중 어긋나면 이 문서를 먼저 고치고 DECISIONS.md에 기록한다.

## 1. 판정 질문 v1, v2

판정 모델(Jev, `jev-1.14.0`)에 한 번의 호출로 함께 보내는 질문 10개이다. 명세서 FR-3, 결정 D4를 따른다. **현행 버전은 v2(1.3절)이다.** 1.1절과 1.2절의 v1은 PoC 기록으로 보존한다.

작성 규칙
1. 질문은 "예"일 확률이 높을수록 위반을 뜻하게 쓴다.
2. 질문 하나에는 조건 하나만 담는다. 조건이 둘이면 나눈다.
3. 경계 설명은 질문 문장이 아니라 참 기준과 거짓 기준(`criteria`의 `true`, `false`)에 쓴다.
4. 한 질문의 결과를 다른 질문의 맥락으로 쓰지 않는다. 질문은 서로 독립이다.
5. 지시와 기준은 입력과 같은 언어로 쓰는 것을 기본으로 한다(공식 권장). 영어 문구는 비교용이다.
6. PoC를 실행하기 전에는 문구를 바꿀 수 있다. 실행한 뒤에는 바꾸지 않고, 바꿔야 하면 새 버전(v2)으로 만들어 이유를 [DECISIONS.md](../DECISIONS.md)에 기록한다.

| 신규 | `service.AnswerGenerator` (인터페이스) | `GeminiService`가 구현한다. `ChatGateway`가 Gemini 코드를 모르게 하고 시험에서 가짜로 바꿔 끼운다. (구현 중 추가) | FR-4, NFR-2 |
| 신규 | `gateway.GatewayResult` | 처리 결과 값(통과 또는 차단, 단계, 패턴 ID, 실패 종류, 판정 결과, 답변). (구현 중 추가) | 5.3 S1 |
| 신규 | `config.GatewayConfig`, `JudgeProperties`, `GatewayProperties` | 설정 값을 읽고 검증해 부품을 만들어 연결한다. 잘못된 설정이면 서버가 시작되지 않는다. (구현 중 추가) | AC-2.4, 3.8 |

### 5.2 요청 흐름

```
POST /api/chat
  └ ChatController
      └ ChatGateway.handle(prompt)
          1. InputValidator ─ 실패 → 400 (판정, 응답 모델 호출 없음)
          2. PatternFilter ─ 일치 → BLOCKED(단계=PATTERN)
          3. Judge.judge() ─ JudgeException → BLOCKED(단계=JUDGE_FAILURE)
             BlockDecider ─ 임계값 이상 → BLOCKED(단계=JUDGE)
          4. 측정 모드가 꺼져 있으면 GeminiService.generateAnswer() → PASSED(답변)
             측정 모드가 켜져 있으면 응답 모델 호출 없이 PASSED(답변 없음)
      GatewayLogger.log(결과)   ← 모든 경로에서 한 번 (예외로 끝나는 경로는 decision=ERROR로 남기고 예외는 그대로 던진다. 7.2절 D15)
  컨트롤러 응답:
      PASSED  → 200 {"answer": ...}
      BLOCKED → 403 {"blocked": true, "message": "정책에 따라 요청이 차단되었습니다"}   (단계와 무관하게 같은 본문)
      측정 모드 → 항상 200 {decision, stage, scores, modelVersion}
```

### 5.3 설계 결정

| 번호 | 결정 | 이유 |
|---|---|---|
| S1 | 차단은 예외가 아니라 반환값이다. 판정 호출 실패만 `JudgeException`으로 오고, `ChatGateway`가 잡아서 차단으로 바꾼다. | 차단은 정상 동작이다. 예외로 다루면 `GlobalExceptionHandler`의 500, 504 변환에 섞여 fail-closed가 깨질 수 있다. |
| S2 | `Judge` 인터페이스에 질문 세트, 임계값, 모델 버전을 넣지 않는다. 구현체(`JevJudge`)가 설정에서 읽는다. | 다른 판정 모델이나 질문 조합(후속 개선 후보)으로 바꿀 때 `ChatGateway`가 바뀌지 않게 한다. |
| S3 | 차단 여부를 정하는 `BlockDecider`는 외부와 무관한 순수 함수로 분리한다. | 임계값 경계(AC-3.6, 3.7)와 질문 누락(AC-3.5)을 빠르고 정확하게 테스트한다(TDD 대상). |
| S4 | 로그는 `ChatGateway`의 끝에서 한 곳에서만 남긴다. | 경로마다 로그를 따로 쓰면 항목이 빠진다(AC-7.1). |

## 6. 판정 호출 설계

상태: 확정 (2026-10-27).

### 6.1 인터페이스

```java
public interface Judge {
    JudgeResult judge(String prompt);          // 실패하면 JudgeException
}
public record JudgeResult(Map<String, Double> scores, String modelVersion, long latencyMillis) {}
public class JudgeException extends RuntimeException {
    public enum Kind { TIMEOUT, RATE_LIMITED, SERVER_ERROR, CONFIG_ERROR, INPUT_TOO_LONG, MALFORMED_RESPONSE }
}
```

`BlockDecider.decide(scores, threshold)`는 점수가 하나라도 임계값 이상이면 차단이다(`>=`, AC-3.6). 설정된 질문 ID 중 하나라도 `scores`에 없으면 `MALFORMED_RESPONSE`로 보고 차단한다(AC-3.5).

### 6.2 Jev 호출 (`JevJudge`)

| 항목 | 값 |
|---|---|
| HTTP 클라이언트 | `RestClient` (사용자 승인 2026-10-27). 스프링이 `RestTemplate`을 후속 버전에서 사용 중단하기로 했고, `spring-boot-starter-restclient`가 이미 pom.xml에 있다. 기존 Gemini 호출은 바꾸지 않는다. |
| 요청 | `POST {judge.base-url}/v1/systemone`, 헤더 `Authorization: Bearer {환경변수 TYPESAFE_API_KEY}` |
| 본문 | `{"model": "jev-1.14.0", "state": 사용자 프롬프트, "questions": {ID: {"type": "noul", "instructions": ..., "criteria": {"true": ..., "false": ...}}}}` (PoC에서 검증한 형식) |
| 직렬화 | 문자열을 직접 이어 붙이지 않고 Jackson으로 만든다. 프롬프트에 따옴표와 줄바꿈이 있어도 JSON이 깨지지 않게 한다. (PoC의 수동 이스케이프는 쓰지 않는다.) |
| 응답 파싱 | `answers[ID].noul`(0~1)과 `model`을 읽는다. 값이 숫자가 아니거나 범위를 벗어나면 `MALFORMED_RESPONSE`이다. |

### 6.3 실패 처리 (FR-6)

| 실패 | `JudgeException.Kind` | 재시도 | 결과 |
|---|---|---|---|
| 연결 또는 읽기 타임아웃 | TIMEOUT | 없음 | 차단 |
| 429, 529 | RATE_LIMITED | 최대 2회, 지수 백오프(200ms, 400ms) | 모두 실패하면 차단 |
| 5xx | SERVER_ERROR | 없음 | 차단 |
| 401, 422 | CONFIG_ERROR | 없음 | 차단, 오류 수준 로그(운영 경보) |
| 400 `max_tokens_exceeded` | INPUT_TOO_LONG | 없음 | 차단 (FR-1에서 걸러져야 하는 경우) |
| 응답 형식 오류 | MALFORMED_RESPONSE | 없음 | 차단 |

- 값 제안: 연결 타임아웃 2초, 읽기 타임아웃 3초. 이유: PoC의 p95는 222ms이고 최대 관측값은 약 550ms였다. 3초는 p95의 10배 이상이어서 정상 지연은 넘기고 장애는 빠르게 감지한다.
- 총 시간 상한은 약 10초이다(타임아웃 3초를 세 번 시도하는 최악의 경우에 백오프 대기를 더한 값). 429, 529가 계속될 때만 해당하며 기존 Gemini 읽기 타임아웃(30초)보다 짧다.
- 타임아웃과 5xx를 재시도하지 않는 이유: 재시도하면 사용자 대기 시간이 늘고, 장애가 길면 요청이 쌓인다. 분류는 모두 fail-closed이다.

### 6.4 질문 세트와 설정

- 질문 문구의 사람이 읽는 원본은 이 문서 1.3절(v2)이다. 코드는 같은 내용을 `src/main/resources/judge/questions.tsv`(4열: ID, 질문, 참 기준, 거짓 기준)로 읽는다. 이 형식은 `tools/poc/make_questions.ps1`이 만드는 `questions_K2.tsv`와 같다.
- 이 파일이 설계서 1.3절과 어긋나지 않게 하려고, 단위 테스트에서 질문 ID 10개와 비어 있지 않은 문구를 확인한다(AC-3.9). 문구 자체의 일치는 `make_questions.ps1`의 출력과 파일 내용을 비교하는 방법으로 구현 단계에서 확인한다.


## 7. 차단 응답, 로깅, 측정 모드

상태: 확정 (2026-10-27).

### 7.1 차단 응답

- 본문 `{"blocked": true, "message": "정책에 따라 요청이 차단되었습니다"}`와 403이다. 패턴 차단, 판정 차단, 판정 실패 차단 모두 같은 객체를 돌려준다(AC-5.1~5.3). 이 객체를 만드는 곳을 하나로 두어 단계별로 달라질 수 없게 한다.

오류 응답 코드(구현 결과): 입력 검증 실패는 400 `INVALID_PROMPT`, 깨진 요청 본문은 400 `INVALID_REQUEST`, 응답 모델 오류는 기존 코드(`UPSTREAM_UNAUTHORIZED`, `UPSTREAM_RATE_LIMITED`, `UPSTREAM_CLIENT_ERROR`, `UPSTREAM_TIMEOUT`, `INTERNAL_ERROR`)이다. 모든 오류의 `message`는 고정 문구이며 외부 응답 본문, 주소, 클래스 이름은 싣지 않고 로그에만 남긴다(D12).

### 7.2 로깅

한 요청에 한 줄이며 `key=value` 형식의 구조화 로그이다.

| 항목 | 내용 |
|---|---|
| `requestId` | 요청 식별자(UUID) |
| `decision`, `stage` | PASS, BLOCK 또는 ERROR. 단계는 NONE, PATTERN, JUDGE, JUDGE_FAILURE이고, ERROR일 때는 VALIDATION(입력 검증 실패), JUDGE(판정자의 예상하지 못한 오류), ANSWER(응답 모델 오류)이다. (구현 중 추가, D15) |
| `patternId`, `failureKind` | 해당할 때만 |
| `errorKind` | decision=ERROR일 때만. 예외 클래스 이름이다. 예외 메시지는 싣지 않는다. (구현 중 추가, D15) |
| `scores` | 질문별 확률 10개 |
| `modelVersion` | 응답의 `model` 값 (AC-3.4) |
| `filterMs`, `judgeMs`, `answerMs` | 단계별 지연 (NFR-3). 실행하지 않은 단계는 키를 싣지 않는다. 판정 시간은 재시도 대기를 포함한 전체 시간이다. |
| `promptLength`, `promptHash` | 기본으로 남기는 값. 해시는 SHA-256 앞 16자리(16진수)이다. |
| `prompt` | `logging.store-raw-prompt=true`일 때만 (AC-7.3, 7.4) |

- 로그에 남기지 않는 것: API 키, `Authorization` 헤더, 요청 URL 전체, 판정 요청 본문 전체, 예외 메시지(주소나 키가 들어 있을 수 있다).
- 해시 방식 제안: 프롬프트 길이가 짧으면 해시로 원문을 추측할 수 있어 완전한 익명화는 아니다. 같은 입력의 반복을 찾는 용도이고, 원문이 필요하면 시험 환경에서 원문 저장을 켠다.
- 키 노출 방지 확인 항목(스텝 7에서 테스트로 확인): 기존 Gemini 호출은 키를 URL 쿼리에 넣는다(`?key=`). 예외 메시지에 URL이 들어갈 수 있고, `GlobalExceptionHandler`의 일반 처리기는 `ex.getMessage()`를 응답 본문에 그대로 싣는다. 키가 응답이나 로그에 나오는지 특성화 테스트로 먼저 확인하고, 나오면 AC-7.2의 위반이므로 수정한다.

### 7.3 측정 모드

- 설정 `gateway.measurement-mode=true`일 때만 동작하고 기본은 꺼짐이다(AC-9.1). 켜진 상태로 시작하면 시작 로그에 경고를 남긴다.
- 켜면 통과와 차단 모두 응답 모델을 호출하지 않고 200으로 `{"decision": "PASS|BLOCK", "stage": ..., "scores": {...}, "modelVersion": ..., "failureKind": ..., "patternId": ...}`를 돌려준다(spec 7장, AC-9.2~9.4). 측정 도구가 모든 문장에서 같은 형식으로 읽을 수 있게 하기 위해서이다.
- 키는 항상 모두 싣고, 해당하지 않는 값은 `null`이다(예: 패턴 차단이면 `scores`와 `modelVersion`이 null). `failureKind`는 판정 호출 실패 차단일 때만 값이 있어서 정책 차단과 구분된다(R9). `patternId`는 패턴 차단일 때만 값이 있다. (2026-10-28 보강)
- 일반 모드(꺼짐)의 응답에는 이 필드가 없다(AC-9.1). 입력 검증 실패는 측정 모드에서도 400이다.
- 같은 컴퓨터 제한(2026-10-29, AC-9.7, 9.8): 측정 응답은 차단 이유를 드러내므로 공격자에게 우회 방법을 알려준다(DECISIONS.md 2026-10-26 차단 응답 형식). 그래서 `ChatController`가 요청마다 "측정 모드가 켜져 있고 접속 주소가 루프백(127.0.0.1, ::1)인가"를 판단하고, 그 결과를 `ChatGateway.handle(prompt, measure)`에 넘긴다. 다른 주소의 요청은 일반 처리(응답 모델 호출, 200 또는 403)를 받는다.
- 주소 판단 기준은 실제 TCP 접속 주소(`getRemoteAddr`)이다. 출발지 주소를 위조하면 TCP 연결이 성립하지 않으므로 우회할 수 없다. 조작할 수 있는 것은 `X-Forwarded-For` 같은 헤더이므로 `server.forward-headers-strategy: none`으로 헤더를 믿지 않게 고정한다(스프링은 클라우드 환경을 감지하면 헤더 처리를 자동으로 켤 수 있다). 전제: 앞단에 역방향 프록시를 두지 않는다. 프록시를 두면 모든 요청이 프록시 주소로 보이므로 그때는 측정 모드를 켜지 않는다.
### 7.4 측정 도구 `run_batch.py` (T12, 2026-10-28 확정)

`backend/scripts/run_batch.py`는 입력 CSV의 문장을 서버로 보내고 결과를 CSV와 요약표로 남긴다. 순수 함수(분류, 행 선택, 집계)와 네트워크 호출을 나누어 순수 함수는 서버 없이 시험한다(Python `unittest`, `backend/scripts/test_run_batch.py`).

- **행 선택(AC-9.5)**: `--split`의 기본값은 `design`이고 `eval`은 `--split eval`로 명시해야 한다(`all`은 없다). 선택한 분할 안에서도 `disallowed_content`와 `bias_injection` 유형, 영어(`lang=en`) `hard_negative`는 보내지 않는다. 제외 건수는 사유별로 출력한다. 제한을 푸는 옵션은 두지 않는다.
- **모드 확인(AC-9.6)**: 첫 요청 전에 고정된 정상 문장(`연차 신청은 어떻게 하나요?`) 1건을 보낸다. 응답에 `decision`이 있으면 측정 모드이다. 없고 `answer`가 있으면 일반 모드이므로 `--allow-answer-model`이 없는 한 한 건도 더 보내지 않고 종료 코드 2로 중단한다(확인용 정상 문장은 일반 모드에서 응답 모델로 갈 수 있다). 서버에 연결할 수 없어도 중단한다.
- **분류**: 일반 모드의 200 답변은 `passed`, 403은 `blocked`(단계 `UNKNOWN`: 일반 모드의 차단 응답은 이유를 숨기므로 판정 실패와 정책 차단을 구분할 수 없다), 400과 5xx와 연결 오류는 `error`이다. 측정 모드의 200 응답은 `decision`이 `PASS`면 `passed`, `BLOCK`이면 `blocked`이고 단계와 실패 종류와 패턴 ID와 점수와 모델 버전을 읽는다.
- **출력 CSV**: 입력 열을 그대로 두고 `result_status`, `result_decision`, `result_stage`, `result_failure_kind`, `result_pattern_id`, `result_model_version`, `result_scores`(JSON 문자열), `result_latency_ms`(도구가 잰 응답 시간), `result_answer`, `result_error`를 덧붙인다.
- **요약(AC-6.5, 8.2, constitution 2장 4항)**: 정책 차단(`PATTERN`, `JUDGE`), 통과, 판정 실패 차단(`JUDGE_FAILURE`), 단계 미상 차단(`UNKNOWN`), 오류를 **별도 열**로 센다. 탐지율은 공격 문장 중 정책 차단 건수를, 오탐율은 정상 문장 중 정책 차단 건수를 **판정을 마친 건**(판정 실패와 오류와 단계 미상을 뺀 건)으로 나눈 값이며, 제외한 건수를 함께 적는다. 레이블별, 유형별, 언어별 표를 낸다. 입력 CSV에 선택 열 `group`이 있고 값이 있으면 그 집합(예: `out_of_scope`)은 정상 문장 집계와 **분리한 별도 표**로 보고한다. 응답 시간은 중앙값과 95백분위를 낸다.

## 10. 6단계 측정 설계

상태: 작성 중 (2026-10-28, 사용자 검토 대기). 승인되면 확정으로 바꾼다. 요구사항은 [spec.md](spec.md) FR-10, AC-10.1~10.7이다. 이 절의 숫자(세트 크기, 비율)는 제안이며 승인 전에는 구현하지 않는다.

### 10.1 원칙

- `eval`은 구성마다 한 번만 실행한다. 결과를 보고 질문, 룰, 임계값, 평가 세트를 바꾸지 않는다. 바꾸면 그 `eval`은 더 이상 손대지 않은 데이터가 아니므로 새 세트가 필요하다. 같은 동결 구성을 오류로 중단된 뒤 다시 실행하는 것은 허용하며 기록에 남긴다.
- `design` 데이터만으로 룰, 질문, 임계값, 세트 구성 기준을 정한다. 동결 전에 판정 점수를 평가 세트에 대해 보지 않는다.
- 세트(일반, 도메인, 현실성)는 섞지 않고 따로 보고한다. 일반 세트는 한국어 86행, 영어 97행, 독일어 25행, 스페인어 1행이며(공격 96, 정상 113), 도메인 세트는 한국어만이다.
- 전송 제한은 그대로 지킨다(AC-9.5). 일반 세트에서도 제한 유형과 영어 hard negative는 보내지 않는다. 도메인 세트는 제한 유형이 아니므로 보낼 수 있다.

### 10.2 비교 구성

| 약칭 | 구성 | 호출 |
|---|---|---|
| B-좁음 | 룰 채택 기준(rule-criteria.md)을 통과하는 좁은 정규식 소수 | 없음(로컬) |
| B-넓음 | 재현율을 우선한 넓은 키워드 룰 | 없음(로컬) |
| S1 | Jev + 질문 v1 | 문장마다 1회 |
| S2 | Jev + 질문 v2 (현행) | 문장마다 1회 |
| S3 | B-좁음 또는 S2가 차단하면 차단 | 없음(이미 가진 결과로 계산) |

- 기준선 룰은 `design` 데이터로만 정한다. DECISIONS.md(2026-10-26)에 기록된 후보 4종의 정규식은 저장소에 남아 있지 않으므로 6-1에서 다시 정하고 저장소에 보존한다. 목록과 개수 상한은 6-1에서 확정한다.
- 기준선 평가는 서버 호출이 없다. 룰 목록과 문장 파일만 있으면 로컬에서 돌린다.

### 10.3 지표

판정을 마친 건은 정책 차단(`PATTERN`, `JUDGE`)과 통과이다. 판정 실패, 오류, 단계 미상은 분모에서 빼고 건수를 따로 적는다(AC-6.5).

| 지표 | 정의 |
|---|---|
| 탐지율 | 판정을 마친 공격 중 정책 차단 건수의 비율 |
| 오탐율 | 판정을 마친 정상 중 정책 차단 건수의 비율 |
| 정밀도 | 정책 차단 중 공격이었던 건수의 비율 |
| F1 | 정밀도와 탐지율의 조화평균 |
| 신뢰구간 | 탐지율, 오탐율, 정밀도마다 윌슨 95% 구간 |

- 유형별(`type`, 도메인은 F1~F4와 경계)과 언어별로 나눈다. 건수가 30 미만인 칸은 구간만 적고 해석하지 않는다(독일어 25행, 스페인어 1행이 해당한다).
- **쌍 비교**: 같은 문장에서 구성 A만 맞힌 건수와 구성 B만 맞힌 건수를 표로 적는다(S1 대 S2, B 대 S2, S3 대 S2).
- **임계값 곡선(AC-10.4)**: 문장의 점수는 질문 10개 중 최댓값이고, 임계값 t에서 최댓값이 t 이상이면 차단한다(현행 규칙과 같다). t를 0.05부터 0.95까지 0.05씩 바꿔 탐지율과 오탐율의 쌍을 계산하고 0.5 지점을 표시한다. 호출이 필요 없다. 곡선 아래 면적은 선택 항목이다.
- **응답 시간**: 도구가 잰 값의 중앙값과 95백분위를 적는다(O4).

### 10.4 도메인 `eval` 구축 절차 (AC-10.5)

도메인 정책(F1~F4)을 검증할 손대지 않은 `eval`이 없다. 도메인 문장 184개는 모두 설계와 PoC에 쓰였고 질문 v2를 그 문장들로 조정했다. 그래서 새로 만든다.

1. **생성 지시문**: 도메인 정책서([domain-policy.md](domain-policy.md))의 F1~F4 정의와 작성 기준(요청 수준, 상세한 방법 설명 금지, 제한 유형 요청 금지)만 담는다. 질문 v2 문구, `design`의 오류 사례, 판정 점수는 생성기에 알리지 않는다. 정상, 위반, 경계 문장을 각각 요청하고 모든 생성기에 같은 지시문을 쓴다.
2. **생성기**: 3~4종(목록은 사용자 확인 대기). 이전 시험 문장을 만든 Gemini와 다른 생성기를 포함한다. 생성기의 이름을 모든 행에 기록한다.
3. **후보 풀**: `docs/eval/domain_candidates.csv`(열: `id`, `generator`, `intended_label`, `intended_group`, `text`). 약 200개를 목표로 한다.
4. **자동 필터**: 중복(정규화 후 같은 문장과 매우 비슷한 문장), 길이, 한국어 여부, 제한 유형 표현을 도구로 거른다. 거른 수를 기록한다.
5. **블라인드 라벨링**: 사용자가 `docs/eval/domain_labeling_sheet.csv`(열: `id`, `text`, `label`, `quality`, `reject_reason`)에서 의도 라벨 없이 라벨(공격, 정상, 경계 정상)과 품질(수락, 거절)을 붙인다. 거절 사유 목록은 사전에 정한다(어색함, 중복, 정책 해당 불명, 제한 유형 접근 등). 의도 라벨과의 일치율을 계산한다.
6. **층화 추출**: 수락된 문장에서 사전에 정한 비율로 뽑는다. 제안: 공격 40개(F1~F4 각 10개), 정상 40개(일반 도메인 정상 25개, 경계 정상 15개). 생성기가 한쪽으로 치우치지 않게 균형을 맞춘다. 판정 점수는 보지 않고, 추출은 난수 고정값(seed)으로 재현 가능하게 한다. 어렵다고 느껴지는 문장을 빼지 않는다.
7. **동결**: `docs/eval/domain_eval.csv`(열: `prompt`, `label`, `type`, `split`, `lang`, `source_category`, `group`. `split`은 `eval`, `lang`은 `ko`, `source_category`는 생성기 이름). 동결 기록은 10.5에 쓴다.
8. **보고용 수치**: 생성 수, 중복 제거 후 수, 수락 수, 거절 사유 분포, 라벨 일치율, 생성기별 비율, 최종 구성.

### 10.6 비용과 위험

- 호출 수는 (일반 세트 209 + 도메인 세트 약 80)문장 × 질문 2종, 약 580회이다. PoC에서 1,104회가 약 0.06달러였으므로 0.03~0.1달러로 추정한다(측정 전에 실제 단가를 확인한다).
- 측정 전에 AUP와 MCA를 다시 읽고 수정일을 비교하고(R8), 크레딧 잔액을 확인한다(R9).
- 도메인 문장과 일반 공격 문장은 외부(Jev)로 전송된다. 제한 유형과 영어 hard negative는 보내지 않는다.

### 10.7 한계 (보고서에 그대로 적는다)

- 합성 문장이라 실제 직원의 질문과 분포가 다르다. 생성기가 여럿이어도 AI가 상상한 문장이라는 점은 같다.
- 라벨러가 한 명이다. 일부를 다른 사람이 따로 라벨링하면 일치도를 낼 수 있다(선택).
- 도메인 세트는 약 80문장이라 신뢰구간이 넓다.
- 일반 세트의 언어 분포가 치우쳐 있고(독일어 25행, 스페인어 1행) 한국어는 86행이다.
- 생성기와 판정 모델의 학습 데이터가 겹칠 수 있다. 겹침 여부는 확인하지 못했다.
- 질문 v2는 `design` 데이터로 조정했으므로 `design` 수치는 낙관적이며 `eval` 수치와 구분해서 보고한다.

### 10.8 현실성 세트 (2026-10-28 사용자 동의)

- 목적: 합성 문장 세트의 결과가 **실제 직원의 말투**에서 얼마나 달라지는지 본다. 합성 문장이 낙관적인 정도를 숫자로 보여 주는 용도이다.
- 구성: 공공데이터포털의 한국국제협력단 인사규정 질의응답 세트(15152718, 이용허락범위 제한 없음)의 질문 25개. 원본은 `docs/eval/koica_hr_questions_raw.csv`에 그대로 보존했고 SHA-256은 [eval/README.md](eval/README.md)에 기록했다. 모두 정상 문장이다. 해외 파견 전용 주제의 문항을 따로 구분할지는 6-3에서 사용자가 정한다.
- 규칙: 생성 지시문과 후보 씨앗에 쓰지 않는다. 질문 v2와 기준선 룰과 임계값을 이 문장에 맞춰 고치지 않는다(질문 v2는 2026-10-27에 고정했고 이 문장을 읽은 뒤 바꾸지 않았다). 원본은 고치지 않는다.
- 보고: 정상 문장 25개뿐이므로 오탐율만 의미가 있다. 오탐 건수와 윌슨 95% 구간을 함께 적고, 구성(기준선, 질문 v1, 질문 v2)마다 따로 보고한다. 건수가 30 미만이므로 구간을 중심으로 해석한다.
- 이 세트로 알 수 있는 것은 정상 문장에 대한 오탐뿐이다. 실제 사람이 쓴 공격 문장(모의 레드팀)은 이 세트에 없으며, 추가 여부는 사용자 결정을 기다린다([handoff.md](handoff.md) 3절).
