# 위협 모델과 데이터 정책

[문제 정의서](problem.md)에서 파생한다. 무엇으로부터 무엇을 지키는지(1~2장), 무엇을 어떻게 탐지하고 처리하는지(3~5장)를 정한다. 일정 때문에 위협 모델과 정책서를 한 문서로 합쳤다(2026-10-29).

상태: 초안 (2026-10-29, 사용자 검토 대기). 6장의 결정 대기 항목이 정해지면 확정한다.

## 1. 위협 모델

### 1.1 구성

```
직원 ──(사내 AI 포털)──> 검사 게이트웨이 ──(가려진 문장)──> 외부 AI (Gemini)
                              │
                              └─ 감사 로그 (원문 없음)
```

### 1.2 행위자

| 행위자 | 의도 | 다루는가 |
|---|---|---|
| 실수하는 직원 | 없음. 업무를 빨리 하려고 명단, 설정 파일, 내부 문서를 붙여넣는다 | **주 대상** |
| 경고를 귀찮아하는 직원 | 가벼운 우회(띄어쓰기, 한글 숫자, 값을 나눠 쓰기) | 일부. 우회 몇 가지를 시험하고 결과를 한계로 적는다 |
| 악의적 내부자 | 의도적 유출(암호화, 이미지, 다른 경로) | 범위 밖. 이 도구는 실수 방지가 목적이다 |
| 외부 AI 제공자 | 받은 문장을 저장하거나 학습에 쓸 수 있다 | **신뢰하지 않는다.** 그래서 나가기 전에 가린다 |

### 1.3 지키는 것

| 범주 | 내용 |
|---|---|
| D1 개인정보 | 직원과 고객의 주민등록번호, 외국인등록번호, 휴대전화 번호, 이메일, 계좌번호, 카드번호 |
| D2 자격증명 | API 키, 액세스 토큰, 개인 키, 비밀번호, 비밀번호가 들어 있는 접속 문자열 |
| D3 회사 기밀 | 미공개 프로젝트 코드명, 고객사 이름, 보안 등급 표시가 있는 문서 |

### 1.4 게이트웨이 자체의 위험 (검사기가 새 유출 경로가 되는 경우)

| 위험 | 대응 |
|---|---|
| 검사하려고 문장을 외부 판정 서비스로 보낸다 | 운영 경로의 탐지는 게이트웨이 안의 코드만 쓴다. 외부 판정 서비스(Jev)는 측정 경로의 채점에만, 가짜 데이터로만 쓴다 |
| 로그에 원문이나 탐지한 값이 남는다 | 로그에는 범주, 개수, 처리 결과, 원문의 길이와 해시만 남긴다. 탐지한 값 자체는 남기지 않는다 |
| 가명과 원래 값의 대응표가 새거나 오래 남는다 | 대응표는 요청 하나(또는 대화 하나)의 메모리에만 두고 응답을 복원한 뒤 버린다. 파일과 DB에 쓰지 않는다 |
| 복원이 틀려 다른 값이나 다른 사람의 값이 들어간다 | 대응표를 요청마다 따로 만들고, 같은 값은 같은 가명으로, 다른 값은 다른 가명으로 바꾼다. 복원 성공률을 측정한다(Z의 하위 지표) |
| 차단 응답이 탐지 규칙을 자세히 알려 준다 | 직원에게는 범주와 개수만 알린다("휴대전화 번호 3건"). 탐지 규칙은 알리지 않는다 |
| 외부 AI가 가명을 원래 값처럼 다루지 못해 답이 틀린다 | 가명을 의미가 드러나는 형태로 만든다(`[전화1]`, `[고객2]`). 답의 쓸모를 Z로 측정한다 |

### 1.5 범위 밖

파일과 이미지, 브라우저 확장(직원이 외부 AI 사이트에 직접 접속하는 경로), 응답의 유해성, 문맥 판정(로컬 모델), 부적절한 사용(D4), 악의적 내부자, 직원 감시와 징계. 근거는 [문제 정의서](problem.md) 6장.

## 2. 처리 단계

| 처리 | 직원이 보는 것 | 외부 AI로 가는 것 |
|---|---|---|
| 허용 | 평소와 같은 답 | 원문 |
| 가림 | 원래 값으로 되돌린 답, 그리고 "휴대전화 번호 2건을 가려서 보냈습니다" 표시 | 가명으로 바꾼 문장 |
| 경고 | 무엇이 들어 있는지와 개수, 그리고 "보내기"와 "취소" 버튼. 보내기를 고르면 가림 처리로 보낸다 | 확인 전에는 없음. 확인 뒤에는 가명으로 바꾼 문장 |
| 차단 | 보내지 않은 이유(범주와 개수) | 없음 |

- 한 문장에서 여러 범주가 탐지되면 가장 강한 처리를 따른다: 차단 > 경고 > 가림 > 허용.
- 경고를 확인해도 원문을 그대로 보내지 않는다. 확인은 "가린 채로 보내도 된다"는 뜻이다.

## 3. 범주별 탐지와 처리

### D1 개인정보

| 항목 | 탐지 (형식 + 검증) | 처리 |
|---|---|---|
| 주민등록번호 | `######-#######` 형식과 생년월일 범위, 검증 숫자 | 가림 |
| 외국인등록번호 | 같은 형식, 뒷자리 첫 숫자 5~8 | 가림 |
| 휴대전화 | `01[016789]-####-####` (하이픈, 공백, 붙여 쓰기 모두) | 가림 |
| 이메일 | 일반 이메일 형식 | 가림. 회사 대표 이메일 등 허용 목록은 허용 |
| 계좌번호 | 은행명이나 "계좌" 근처의 숫자-하이픈 묶음 | 가림 |
| 카드번호 | 13~19자리 숫자와 Luhn 검사 | 가림 |
| 대량 | 한 문장에 D1 값이 20개 이상(제안) | 경고 |

### D2 자격증명

| 항목 | 탐지 | 처리 |
|---|---|---|
| 알려진 키 형식 | 주요 클라우드와 서비스의 접두어 형식(예: `AKIA`, `AIza`, `sk-`, `ghp_`, `xox`) | 6장 결정 대기 |
| 개인 키 | `-----BEGIN ... PRIVATE KEY-----` 블록 | 6장 결정 대기 |
| 비밀번호 할당 | `password=`, `pwd:`, `비밀번호:` 같은 표시 뒤의 값 | 6장 결정 대기 |
| 접속 문자열 | 사용자와 비밀번호가 들어 있는 DB 접속 URL | 6장 결정 대기 |
| JWT | 점 두 개로 나뉜 base64url 세 덩어리 | 6장 결정 대기 |

### D3 회사 기밀 (회사 사전, 설정 파일)

| 항목 | 탐지 | 처리 |
|---|---|---|
| 프로젝트 코드명 | 사전의 단어와 일치 | 가림 |
| 고객사 이름 | 사전의 단어와 일치 | 가림 |
| 보안 등급 표시 | "대외비", "사내한", "Confidential", "Internal Only" 같은 표시 | 차단 |

회사 사전(코드명, 고객사, 등급 표시, 허용 목록)은 가상의 회사로 만든다. 형식은 [더미 회사 설정](dummy-company.md)(2일차 작성)에 둔다.

## 4. 경계 규칙

- **형식을 묻는 질문은 정상이다.** "주민등록번호는 몇 자리야?", "API 키는 어디에 저장해야 해?"처럼 값이 없으면 탐지하지 않는다.
- **검증에 실패하는 값은 탐지하지 않는다.** `000000-0000000`, `010-0000-0000`, `sk-xxxx`처럼 명백한 예시 값은 정상으로 본다. 오탐을 줄이기 위한 핵심 규칙이다.
- **누구의 정보인지는 판단하지 않는다.** 게이트웨이는 그 값이 본인 것인지 고객 것인지 알 수 없다. 본인 것이어도 가린다. 가림은 업무를 막지 않으므로 비용이 작다.
- **회사의 공개 정보는 허용한다.** 대표 전화, 대표 이메일, 공개 홈페이지 주소는 허용 목록에 넣는다.
- **가림은 값만 바꾸고 문장은 바꾸지 않는다.** 요청의 의도와 형식은 그대로 둔다.

## 5. 기록

- 감사 로그 한 줄: 요청 ID, 시각, 범주별 개수, 처리 결과, 원문의 길이와 해시, 단계별 지연.
- 남기지 않는 것: 원문, 탐지한 값, 가명 대응표, API 키.

## 6. 결정 대기 항목

| 번호 | 항목 | 후보 | 권장 |
|---|---|---|---|
| P1 | D2 자격증명의 처리 | 가 차단 / 나 가림 | **가 차단.** 자격증명이 채팅에 붙여넣어진 것 자체가 사고 신호이고, 가려서 보내도 직원이 같은 습관을 이어 가게 된다. 차단 메시지에서 "값을 지우고 다시 보내세요"라고 안내한다. 가림을 택하면 설정 파일 디버깅 같은 업무는 계속할 수 있다 |
| P2 | D1 대량 경고의 기준 | 10개 / 20개 / 50개 | **20개.** 근거는 없고 출발점이다. `design` 데이터로 정하고 측정 전에 동결한다 |
| P3 | 경고 확인 뒤의 처리 | 가 가림으로 보냄 / 나 원문으로 보냄 | **가 가림.** 원문 전송을 허용하면 경고가 우회 수단이 된다 |
