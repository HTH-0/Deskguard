====================================================
3단계 — 프록시 API 골격: 파일 구조와 요청 흐름
====================================================

■ 요청이 실제로 흘러가는 순서
--------------------------------------------------
1) 사용자(Postman)가 POST http://localhost:8080/api/chat 에 {"prompt":"안녕"} 을 보냄
2) ChatController가 이 요청을 받음
   - @RestController가 붙어있어서, 메서드가 리턴하는 객체를 자동으로 JSON으로 바꿔줌
   - @RequestBody가 붙은 ChatRequest 파라미터에 {"prompt":"안녕"}이 자동으로 채워짐
3) ChatController는 실제 작업을 GeminiService에게 그대로 넘김 (chat 메서드 안에서 geminiService.generateAnswer(...) 호출)
4) GeminiService가 실제로 하는 일:
   a. application.yml에서 읽어온 API 키/모델명/URL로 Gemini에 보낼 주소를 조립
   b. GeminiRequest.of(prompt) 로 {"contents":[{"parts":[{"text":"안녕"}]}]} 모양의 요청 객체를 만듦
   c. RestTemplate.postForObject(...) 로 실제 HTTP POST를 Gemini 서버에 보냄
   d. Gemini가 준 응답을 GeminiResponse 객체로 자동 변환받음 (Jackson이 JSON -> 자바 객체 변환)
   e. response.extractAnswerText() 로 candidates[0].content.parts[0].text 만 뽑아냄
5) 다시 ChatController로 돌아와서, 그 답변을 ChatResponse(answer) 로 감싸서 리턴
6) 스프링이 이 ChatResponse를 자동으로 {"answer":"..."} JSON으로 바꿔서 사용자에게 응답

만약 중간에 문제가 생기면(키가 틀림, 타임아웃 등):
- GlobalExceptionHandler가 대신 잡아서, 서버가 죽지 않고 항상 정해진 JSON 모양의 에러를 돌려줌


■ 파일별 역할 한눈에 보기
--------------------------------------------------
backend/
├── pom.xml                                  프로젝트 설정 (어떤 라이브러리를 쓸지, 자바 버전 등)
├── .gitignore                               target/, 키 파일 등 git에 올리면 안 되는 것들
├── scripts/run_batch.py                     dataset.csv를 읽어 /api/chat을 자동으로 여러 번 호출하는 도구
└── src/main/
    ├── java/com/promptgateway/
    │   ├── PromptGatewayApplication.java    시작점 (이 파일의 main()을 실행하면 서버가 뜬다)
    │   ├── controller/ChatController.java   요청을 받는 창구. "무엇을 어디서 받을지"만 담당
    │   ├── service/GeminiService.java       실제로 Gemini를 호출하는 로직. "어떻게 처리할지" 담당
    │   ├── dto/
    │   │   ├── ChatRequest.java             우리 서버가 받는 요청 모양 {"prompt": "..."}
    │   │   ├── ChatResponse.java            우리 서버가 주는 응답 모양 {"answer": "..."}
    │   │   └── gemini/
    │   │       ├── Part.java                Gemini JSON의 가장 안쪽 조각 {"text": "..."}
    │   │       ├── Content.java             Part들을 담는 상자 {"parts": [...], "role": "..."}
    │   │       ├── GeminiRequest.java       우리가 Gemini에 보내는 요청 전체 모양
    │   │       ├── GeminiResponse.java      Gemini가 주는 응답 전체 모양 + 답변 꺼내는 메서드
    │   │       ├── Candidate.java           응답 안의 candidates 배열 원소
    │   │       └── UsageMetadata.java       토큰 사용량 정보
    │   ├── config/RestTemplateConfig.java   RestTemplate(외부 API 호출 도구)을 등록 + 타임아웃 설정
    │   └── exception/
    │       ├── GlobalExceptionHandler.java  모든 에러를 한 곳에서 붙잡아 정해진 JSON으로 응답
    │       └── ApiErrorResponse.java        에러 응답의 통일된 모양 {"error": "...", "message": "..."}
    └── resources/application.yml            포트 번호, API 키(환경변수 참조), 모델명 등 설정값


■ 왜 컨트롤러/서비스/DTO를 나눴는가
--------------------------------------------------
- 컨트롤러: "요청을 받고 응답을 돌려주는" 역할만. Gemini가 뭔지도 몰라도 됨
- 서비스: "Gemini를 어떻게 부르는지" 아는 유일한 곳. 4단계에서 필터 로직이 추가돼도
  이 계층 근처만 건드리면 되고 컨트롤러는 거의 안 바뀜
- DTO(Data Transfer Object): JSON 모양을 그대로 자바 클래스로 옮겨둔 것들.
  Jackson이 이 클래스들을 보고 JSON <-> 자바 객체 변환을 자동으로 해준다


■ 실제로 겪은 문제들 (DECISIONS.md에도 기록됨)
--------------------------------------------------
1. 이 컴퓨터에 JDK/Maven이 없어서 새로 설치함 (JDK: winget, Maven: 공식 zip)
2. 컴파일 에러: RestTemplateBuilder의 타임아웃 메서드가 connectTimeout()이 아니라
   setConnectTimeout()이었음 (스프링부트 3.2.5 기준) -> 컴파일해보고 바로 잡음
3. Gemini는 잘못된 키에 401이 아니라 400을 반환한다는 걸 발견.
   그리고 Bash 터미널에서 curl에 한글을 직접 넣었을 때 깨지는 걸 발견했는데,
   이건 서버 문제가 아니라 터미널이 명령줄 인자를 넘기는 방식의 문제였음
   (파일로 넘기니 바로 해결 - 자바/Jackson 자체는 원래부터 UTF-8을 문제없이 처리함)
4. "버전이 옛날 것 같다"는 지적을 받고 검색해보니, 처음 쓴 스프링부트 3.2.5는 물론
   3.x 라인 전체가 이미 지원 종료(EOL) 상태였음 -> 4.1.1로 업그레이드.
   그 과정에서 또 API가 바뀐 걸 2개 발견:
     - RestTemplateBuilder가 spring-boot-starter-web에서 빠지고
       spring-boot-starter-restclient라는 별도 모듈로 이동함 (의존성 추가로 해결)
     - 그 새 모듈에서는 타임아웃 메서드명이 connectTimeout()으로 다시 바뀜
       (2번에서 고쳤던 setConnectTimeout()이 이번엔 틀린 이름이 됨 - 메이저 버전이
       바뀌면 이렇게 API 명칭이 왔다갔다 할 수 있다는 걸 실제로 겪은 사례)


■ 버전에 대한 교훈
--------------------------------------------------
AI(Claude)의 지식도 특정 시점까지의 정보라, 계속 바뀌는 라이브러리 버전 같은 건
몇 달만 지나도 틀릴 수 있다. "버전이 옛날 것 같다"처럼 의심이 들면 실제로 검색해서
확인하는 게 맞다 - 이번에도 검색해보니 처음 골랐던 버전이 이미 지원 종료 상태였다.
